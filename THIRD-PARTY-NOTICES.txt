Changes made in this project, 2026-11-02:
- Restrict transport to shared-access USB DualSense/Edge gamepad interfaces.
- Remove all input/remapping, audio, haptics and trigger generation.
- Add foreground-only effects and a background lighting-validity guard.
- Add normalized settings, Dalamud configuration and regression checks.

Bluetooth output extension, 2026-11-04:
- Extend the common DualSense lighting fields to standard 78-byte report 0x31.
- Retain the legacy DS4Windows Bluetooth header when guarding an existing report.
- Add compatible rumble fields with the existing DS4Windows validity-bit meanings.
- Use a per-device four-bit sequence and IEEE CRC-32 seeded with transaction byte 0xA2.
The standard Bluetooth header/common-block layout is also documented in Sony's
Linux hid-playstation driver (protocol reference):
https://github.com/torvalds/linux/blob/master/drivers/hid/hid-playstation.c
Bluetooth codec, sequencing and the shared output owner are implemented locally;
this adds no controller driver, remapping service or bundled upstream executable.

Bluetooth compatible rumble v2, 2026-11-04:
Firmware capability metadata, feature CRC seed 0xA3 and the feature-version 2.21
threshold follow the hid-playstation protocol reference above. The two-phase
strength test, bounded impact pulse renderer and stereo rumble handoff reuse
original plugin components. The physical protocol reference distinguishes
compatible motor rumble from full audio haptics.

The earlier local Steam Lighting Guard prototype was reused for the narrow
Dalamud WriteFile/HidD_SetOutputReport interception approach. It is not shipped
as a separate dependency and must be disabled before loading this replacement.

src/DualSenseLighting/Windows/SfxAudioCapture.cs adapts the source-render and
CoreSystem global signatures from that revision. The callback-vtable signature
and source-layout checks were verified against the local game executable.
The SoundManager singleton and sound-pool acquisition signature also follow that
revision. The playback-ID getter, pool slot layout and VFX sound-callback field
accesses were independently checked in the local executable. Player-only filtering
uses caster identity rather than volume category.
The positional sound-entry lookup, logical handle at entry+0x38 and embedded
controller playback ID at entry+0x10 were independently checked through local
disassembly and read-only comparison with active mixer voices. The observer
retains the game's original lookup, arguments and return value.
The character-sound callback uses VfxContainer.LoadCharacterSound's signature
and ContainerInterface.OwnerObject at +8. The local model tree uses Scene.Object's
parent/child/sibling fields and its type getter to include weapon/character models
while excluding attached VFX objects. Model refreshes do not reset actor ownership.
The action timeline owner uses SchedulerTimeline's vfunc 29 and its checked
owning-object-index field at +0x18C. The sound-clip update signature was researched
in Penumbra.GameData; the clip-to-timeline resolver and its call ordering were
verified independently in the local executable. Existing native calls and their
return values are preserved; the plugin does not walk mutable scheduler lists.
Delayed C012 effect ownership reuses that timeline observer and Scene.VfxObject's
ResourceInstance field at +0x2A0. The clip/container/scene-handler link, concrete
scene getter, listener at +0x90 and constructor signature were verified in the
installed executable and trace metadata. A separate read-only constructor observer
invalidates reused effect addresses; a bounded cache matches the exact listener,
resource instance and immutable caster identity. No VFX creation, asset or playback
parameters are changed, and no VFXEditor implementation is bundled.
NpcSpawnMetadata adapts the NPC packet's minimal relationship and status-source
fields. NpcSpawnObserver uses PacketDispatcher.HandleSpawnNpcPacket's signature,
verified as a unique 0x290-byte queueing handler in the installed executable. It
is enabled only during an explicit diagnostic trace, preserves the original call
and arguments, and does not interpret tethers, events or link families as owners.
The source observer reads audio for RGB loudness and optional character combat
haptics. Original samples, source sends and native playback are not changed.

src/DualSenseLighting/Windows/NativeHapticOutput.cs additionally adapts the
CoreSubmixVoice layout, Instances signature and MixIn virtual-function signature:
FFXIVClientStructs/SQEX/Sd/Driver/Core/CoreSubmixVoice.cs
The native MixIn implementation, source-send call ordering, vibration submix name,
format and effect presence were checked against the local executable and a
read-only inventory of the running game. Optional character haptics adds approved
PCM to that existing native submix. Existing vibration sends are not duplicated;
no upstream DSP implementation or mod audio assets are bundled.

GameHapticCamera reads the active camera's view orientation and position on the
framework thread. The direction origin comes from Dalamud's local-player Position
property; the distance origin can be character or camera. SoundData positional coordinates and flag were independently
checked in the native sound-creation path. The stereo conversion-matrix builder,
vibration filter's per-channel processing and controller endpoint channel copy were
researched in local disassembly. Native conversion is called only to create private
matrices; source voice setters and game camera state are not modified. A separate
PCM buffer is used for spatial haptics; no original playback buffer is replaced.
HapticStereoMatrix converts the native builder's padded input rows into compact
output rows, retaining its intentional crossfeed. This layout and the int return
status were checked against the installed executable's native arithmetic in an
isolated process, in addition to disassembly and recorded source metadata.

The opt-in native footstep amplifier reads the existing CoreSourceVoice send gain
and the Foot sound-bus ID from the same revision. It adds only the requested extra
gain to an already-present native vibration send while the character is unmounted.
Original PCM, sends, source gains and speaker routes are not changed.

The combat-enable confirmation uses the same CoreSubmixVoice vibration format.
Its short-lived render hook was identified and validated in the installed mix
pass by local disassembly; the original render callback and result are retained.
The CoreSystem.SampleRate signature follows the upstream CoreSystem binding.
The confirmation waveform and scheduler are original plugin code.

Limit Break indicator detection adapts the read-only gauge layout and singleton
signature, and action-effect header/Receive signature, from the same revision:
FFXIVClientStructs/FFXIV/Client/Game/UI/LimitBreakController.cs
FFXIVClientStructs/FFXIV/Client/Game/Character/ActionEffectHandler.cs
The singleton signature and action-effect call signature each matched once in the
installed executable; the target callback prologue/header access were checked in
local disassembly. The observer retains the original callback and arguments.
Cast state comes from Dalamud; action identities come from Lumina's installed game
data. Dalamud provides the Lumina assemblies; they are not bundled in this plugin.

The C063 sound entry size/header, native SoundClip type/data field, scheduler
actor constructor, vtable and binding-selector field were independently checked
against local game files and executable code. The observer reuses the existing
clip-to-timeline call and does not parse or load timeline files on audio callbacks.
Default/target tracks in confirmed skill execution timelines can route as boss
effects. The native C063 position resolver independently verifies its data+0x14
positional/bind flags and data+0x15 bind index. Duration-one positional caster
origin entries can also qualify when the same actor/timeline metadata has an
unambiguous recognized AttackType (installed rows 1..8). Bone-bound execution,
cast-start, voice, unknown and basic-attack tracks retain their prior exclusions.
No sound filename or NPC/skill allowlist is used for this extension.
