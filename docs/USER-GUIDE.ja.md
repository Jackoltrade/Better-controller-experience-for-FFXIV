# Better controller experience for FFXIV — ユーザーガイド

[クイックスタート](../README.ja.md)

[English](USER-GUIDE.md) · [简体中文](USER-GUIDE.zh-CN.md) · [日本語](USER-GUIDE.ja.md)

DualSenseのライトと振動をFFXIVに合わせて楽しめる、Dalamud用プラグインです。自分のスキル、敵の効果音、カメラの揺れを振動で伝え、ゲーム標準のDualSense機能も維持します。

**Windows x64 · Dalamud API 15**

このガイドの診断タブと診断コマンドは、開発用プラグインとして読み込んだ場合のみ利用できます。

## 主な機能

- **RGBライト：** 単色、レインボー、ゆっくり明滅、2色グラデーション、オーロラ、炎、ハートビート、コメット、レインボーパルスと、音に連動する2つのモード。
- **下側のLED：** タッチパッド下の5つの白いライトの点灯数や動き方を選び、LBの状態も表示できます。
- **戦闘の振動：** 自分のスキル・武器、ボス、通常の敵のスキル、被ダメージ時の効果音を個別に設定できます。
- **方向と距離：** 自キャラクターを中心に、カメラの向きに合わせて左右の振動を調整し、遠い音は弱められます。
- **画面エフェクト：** カメラの揺れ、放射ブラー、方向ブラー、ガウスぼかし、色収差に連動します。
- **標準の足音振動を強化：** USB DualSenseの既存の足音振動だけを強め、マウントやスピーカー音には影響しません。
- **プレビューと3言語：** ライトのプレビューと音の反応メーターを備え、日本語・英語・簡体字中国語を切り替えられます。

別のアプリに切り替えると、ライトを一度消灯して制御を手放し、追加の振動をすべて一時停止します。ゲームに戻るか接続し直すと、保存した設定が再び反映されます。設定はDalamudに保存し、コントローラーのファームウェアに恒久的に書き込むものではありません。

## 対応環境

| コントローラーと接続方法 | ライト | プラグインが追加する振動 |
| --- | --- | --- |
| ソニー DualSense / DualSense Edge、USB | RGB・下側LED | 精細なネイティブハプティクス、戦闘・画面エフェクト、足音振動の強化 |
| ソニー DualSense / DualSense Edge、Bluetooth | RGB・下側LED | 戦闘・画面エフェクトによる通常振動 |
| Xbox互換XInput、USB・ワイヤレス | 制御しません | 戦闘・画面エフェクトによる通常振動 |

- Windows x64、FFXIV、**Dalamud API 15**が必要です。他のOSや、DirectInputのフォースフィードバックには対応していません。
- 精細なDualSenseハプティクス、標準の足音・マウントの質感、コントローラースピーカーには**USB接続**が必要です。FFXIVの振動を有効にし、DualSense機能はゲーム内で通常どおり設定してください。
- Bluetooth DualSenseにはHIDコマンドを直接送るため、変換ソフト、仮想コントローラードライバー、常駐アプリは不要です。Bluetoothでの音声ハプティクスのストリーミングやスピーカー音声は提供しません。
- XInputでは、追加分をゲーム本来のモーター指令と合成します。DirectInput専用機器にはXInput変換ソフトが必要です。ボタンの割り当て変更やコントローラーのペアリングは行いません。

本プラグインはカスタムリポジトリで配布しており、Dalamud公式リポジトリの審査は受けていません。ネイティブの音声・カメラ処理は、XIVLauncherCNとクライアント `2026.10.06.0000.0000` で確認しています。開発環境でのユーザーテストでは、USBの標準機能と、Bluetoothのライト・振動・方向・距離を確認していますが、すべての機種・ファームウェア・リージョン・今後のパッチでの動作を保証するものではありません。[QAレポート](QA-REPORT.md)に、自動チェック、過去の実機結果、未確認事項を分けて記載しています。対応していないネイティブ構造では該当機能を停止し、診断タブに理由を表示します。

## 導入

すべての表示言語で、下記の共通リポジトリを使います。公開済みのパッケージは[リリースページ](https://github.com/Jackoltrade/Better-controller-experience-for-FFXIV/releases)からもダウンロードできます。

### Dalamudインストーラーを使う

1. `/xlsettings` → **Experimental** → **Custom Plugin Repositories**を開きます。
2. 次のURLを追加します。
   ```text
   https://raw.githubusercontent.com/Jackoltrade/Better-controller-experience-for-FFXIV/main/repo.json
   ```

   インストーラーの説明文は英語（中国語版ランチャーでは中国語）です。プラグインの画面は日本語・英語・中国語に切り替えられます。従来のリリース配布用URLも引き続き使えます。
3. `/xlplugins`で **Better controller experience for FFXIV** を検索し、「Install」を選びます。
4. コントローラーを接続し、`/bcef`を実行します。

Dalamudのテスト版設定を有効にする必要はありません。

### 手動・開発用プラグインとして導入する

1. [リリースページ](https://github.com/Jackoltrade/Better-controller-experience-for-FFXIV/releases)から `latest.zip` をダウンロードするか、ローカルでビルドした `artifacts/plugin/` を使います。
2. ZIPを使う場合は、全体を専用フォルダーに展開します。
3. `/xlsettings` → **Experimental** → **Dev Plugin Locations**に、そのフォルダーの `DualSenseLighting.dll` を追加します。
4. `/xlplugins` → **Dev Tools**で有効にします。

同時に複数の方法で読み込まないでください。以前の **Steam Lighting Guard** は先に無効にし、インストーラーへ移行する際は開発用の登録を削除してください。既存の設定と開発用パスを引き継ぐため、DLL名と内部IDは `DualSenseLighting` のままです。無効化・削除は、導入時と同じインストーラーから行えます。

## 最初の設定

1. 精細なハプティクスにはDualSenseを**USB接続**します。ワイヤレスのライトと通常振動には、先にWindowsで**Bluetoothペアリング**してください。XInput機器は通常どおり接続します。
2. USB DualSenseではFFXIVの振動を有効にし、使いたい標準の振動・スピーカー機能が動くことを確認します。
3. 初回読み込み時の案内を確認し、ライトと振動を有効にするか選びます。新規インストールでは両方オフ、既存の設定がある場合は保存済みの選択が表示され、一度だけ確認します。**選んだ効果を有効にする**か**効果をオフのままにする**で確定してください。左上の**使い方**または `/bcef info` で再表示できます。
4. **振動 → 振動出力**を開きます。「自動」はUSB DualSenseハプティクス、DualSense Bluetooth振動、XInputコントローラー1台の順に選びます。複数の機器や変換ソフトを使う場合は手動で指定してください。XInputは最初に接続された機器か、番号1～4を選べます。
5. スキルを使い、**自分の振動の強さ**と**敵の振動の強さ**を調整します。Bluetooth・XInputでは、下記の通常振動設定も使えます。
6. 一度別のアプリに切り替えて戻り、ライトの引き渡しを確認します。ゲーム中に接続し直した場合も、設定が復帰し、古い振動が再生されないことを確認できます。

選択を保存するまでは、コントローラーの出力、ゲーム内部の音の監視、追加振動を開始しません。案内を閉じるか**後で**を選ぶと停止したままになります。案内には内部関数へのフック、互換性、PC内での処理についても記載しています。確認済みの状態は案内を閲覧したかどうかとは別に保存し、タブの初期化では消えません。

項目や **(?)** にカーソルを合わせると説明が表示されます。操作できない項目でも確認できます。上位スイッチをオフにすると下の項目は無効になりますが、値は消えません。変更は自動保存されます。タブ上部の **Language / 语言 / 言語** で即座に言語を切り替え、選択を保存できます。

**初期設定に戻す**は、確認後に現在のライティングまたは振動タブだけを初期化します。キャンセル、閉じる、Escape、ポップアップの外側のクリックでは変更しません。もう一方のタブと言語は維持されます。更新時も保存済みの選択を引き継ぎ、新しい初期値で明示的な設定を上書きしません。

## ライティング

左右のライトは1つのRGB色を共有します。LEDを1つずつ指定するインターフェースがないため、ライトに沿って移動する波は作れません。

効果、明るさ、対応する色、周期を選べます。単色は1色、2色グラデーションは2色を使い、オーロラと炎はプリセットの配色です。RGBと下側LEDの周期は別々です。プレビューは実際の出力と同じ計算を使います。

| 音に連動するモード | 動き |
| --- | --- |
| 音量連動 | 音が大きいほど選んだ色が明るくなり、静かになると消えます。 |
| 音量で色変化 | 静かな時の色から大きな音の色へ変わり、音がない間も静かな時の色が残ります。 |

**自分のキャラクターのみ**は自分のアクションと武器の音に反応し、**すべての戦闘音**は周囲のプレイヤーと敵も含めます。この選択はライト専用で、振動には個別の分類スイッチがあります。ゲームの効果音を読み取り、マイクやデスクトップ音声は取得しません。

スキルを使いながら、**音への感度**の下のメーターを見て調整します。常にいっぱいなら下げ、静かなスキルで動かなければ上げてください。**光が消える時間**または**色が戻る時間**で反応の収まり方を変えます。小さな音の自動除外は感度に合わせて働きます。**サウンドの詳細設定**では自動設定をオフにして基準を調整できますが、高すぎると静かなスキルを拾えません。ゲームの音量は変わりません。

**下側のLED**は消灯または1～5個を選び、常時点灯・チェイス・バウンス・点滅・ハートビート・きらめき・ローディングから動き方を選べます。チェイス・点滅・ローディングは選んだ位置の中で動きます。バウンスときらめきは5つの位置を使い、数の設定で同時点灯数を指定します。ハートビートは選んだ数が一緒に光ります。チェイスの移動を見るには2個以上、バウンスには5個未満を選んでください。

**リミットブレイク**モードでは、PvEでパーティの使用可能なLBゲージ数、PvPで自分の蓄積量を表示し、自分のLBの詠唱・使用時に速く点滅します。点滅・ローディングの周期はRGBと別です。有効なゲージがない場合やLB処理が非対応の場合は、診断タブに停止理由を表示します。

## 振動

### 一括スイッチと戦闘の分類

**振動を有効にする**で、プラグインが追加するすべての振動を切り替えます。下に**戦闘**、**画面エフェクト**、**足音振動の強化**があり、一括スイッチをオフにするとすべて停止して設定を保持します。ゲーム本来の振動、スピーカー音声、トリガー指令はゲーム側の動作を維持します。

**戦闘振動を有効にする**は、**自分の効果音に連動**、**ボスのスキル**、**通常の敵のスキル**、**被ダメージ時の振動**をまとめて切り替えます。オフにしても、画面エフェクトと足音の強化は使えます。

| 戦闘の分類 | 対象 |
| --- | --- |
| 自分の効果音に連動 | 自分のスキルと武器の音。自分用の強さで調整します |
| ボスのスキル | コンテンツ内のボス戦で、発生元を確認できたNPCや対象のフィールドギミックの音。通常攻撃、詠唱、予告音も含みます |
| 通常の敵のスキル | 通常の敵対モンスターの確認済みスキル効果。通常攻撃は除外します |
| 被ダメージ時の振動 | 通常攻撃を含む敵の攻撃で発生する、自分の被弾・ガード音。個別に切り替えられます |

**敵の効果音に連動**グループの**ボスのスキル**、**通常の敵のスキル**、**被ダメージ時の振動**は、**敵の振動の強さ**を共有し、**自分の効果音に連動**とは個別に使えます。ゲームがすでに振動として送っている音は二重に追加しません。聞こえる効果音、スピーカー音量、アダプティブトリガーは変更しません。

**ボスの分類：**インスタンスコンテンツで、自分と認識済みのボスがともに戦闘中になると、「ボスのスキル」の対象を広げます。参加人数に制限はありません。確認済みのNPC音源か、対象となるフィールドギミックの音源が必要です。発生元が不明な音、ほかのプレイヤー、ペット、プレイヤー側と確認できたNPCは含めません。音楽、台詞、UI音、ループするフィールド環境音は除外します。「ゲームの全音声」に反応するモードではありません。

プラグインは**ボス戦の前**に通常の敵と判別した敵対NPCを記憶します。追加振動をオフにしていても記録し、その個体は戦闘中も通常の敵のスキルとして扱います。戦闘終了、別アプリへの切り替え、機能のオン・オフでは消えず、エリア・コンテンツ・プレイヤーのエンティティ変更や再読み込みで初期化します。戦闘中に初めて見つかった通常の敵がボス側に含まれる場合はあります。戦闘途中に再読み込みしても以前の記録は戻りません。この分類で、すべての新規NPCをボスの召喚物と断定しているわけではありません。

コンテンツ内のボス戦条件を満たさない間は、確認済みのスキルと関連ギミックのフィルターを使います。認識できるボスF.A.T.E.とB・A・Sランクのリスキーモブはボス側、通常のF.A.T.E.の敵は通常の敵として扱います。判別には [LuminaSupplementalのデータ](../data/README.md)とインストール済みゲームデータを使い、未認識のボスだけでは対象を広げられません。発生元・再生方式が不明な音や、分類が曖昧なスキルの一部は未対応です。1つのギミックの確認で全ボス対応を保証するものではありません。[敵の振動の対応範囲と制約](ENEMY-HAPTICS-COVERAGE.md)もご覧ください。

### USB・Bluetooth・XInput出力

USB DualSenseでは、ゲームの振動処理を通して音の細かな質感を伝えます。Bluetooth・XInputの通常振動は、対象の戦闘音の立ち上がりを短い衝撃に変え、長い音の間ずっと振動し続けるのを避けます。ライトをオフにしても振動は使えます。

**振動出力 → 通常振動**で調整できます。

- **通常振動の強さ：**戦闘の通常振動の上限で、初期値は**50%**です。自分・敵の強さと距離減衰も適用されます。画面エフェクトは別の強さを使います。
- **1回の振動時間：**初期値**120ms**、範囲**60～300ms**。長いほど重い衝撃になります。
- **振動の強弱をテスト：**設定した上限で、弱い振動と強い振動を少し長めに再生します。
- **左右の振動をテスト：**現在の強さと左右バランスで、左、右の順に振動します。

テスト時は立ち止まってください。他の追加振動は短時間停止し、別のアプリに切り替えるとテストを中止します。USBのネイティブ出力では設定・テストを表示しません。USB接続時の自動モードも同様です。通常振動の出力先は1台ですが、ライトは複数のDualSenseに適用できます。

Bluetoothでは、戦闘の方向設定による左右の強さを維持します。左は重い低周波、右は軽い高周波の振動で、同じ指令値でも感触が違うことがあります。**Bluetooth振動の左右バランス**の初期値は**+85%**。左の指令を15%に下げ、右は変えません。プラスは左、マイナスは右を弱め、0では同じ指令を送ります。戦闘・画面エフェクトの合成後と、有効化の通知・テストにも適用されます。感触に合わせて調整してください。ユーザーが選んだ初期値であり、自動校正でも、両側の質感を同じにする設定でもありません。保存済みの調整値は維持されます。

対応するBluetoothファームウェアでは改良通常振動を使います。診断にはモードと現在のモーター指令を表示し、テスト後も結果を残します。XInputでは周波数の異なるモーターを使い分け、精密な左右定位は行わず、ゲーム本来の指令と合成します。変換ソフトの仮想Xbox機器を使う場合はXInputを明示的に選べます。自動モードは検出可能な実機DualSenseを優先します。

### 共通の方向・距離設定

**戦闘振動の詳細設定**は、自分・ボス・通常の敵・被ダメージ時・フィールドギミックの振動に適用します。**自分の効果音に連動**をオフにしても操作できます。

**音の方向を振動に反映**する際は、自キャラクターの位置を中心に、カメラの向きで左右を判断します。キャラクターの向きには依存しません。**距離で振動を弱める**設定は個別に使えます。推奨のキャラクター基準では**3m**まで最大の強さを保ち、**25m**でゼロになります。距離減衰中に音源や基準の位置が不明な場合は、その追加戦闘振動を停止します。標準の振動は別に維持されます。

距離の基準は**カメラ**にも変更できます。推奨範囲にキャラクターとカメラの距離を加え、ズームに合わせて調整します。**推奨の距離設定を使う**をオフにすると手動で指定でき、2つの基準の範囲は別々に保存されます。キャラクター基準はズームの影響を受けません。

**自分の効果音の設定 → スキルの着弾方向に寄せる**は、キャラクター付近の武器・詠唱音を、自分のスキルの直近の聞こえる着弾方向へ寄せます。**自分の効果音に連動**と方向反映の設定が必要です。**着弾方向に寄せる強さ**は**25～100%**で、方向だけを変え、音源の距離は変えません。スキルが重なる場合の誘導は近似です。診断の左右メーターは計算上の強さで、実機の振動を測定した値ではありません。

### 画面エフェクト

実際のカメラの揺れと、対応するブラー・色収差に連動し、他の振動と同時に再生して合成後の強さを制限します。終了した効果を後から再生しません。普通のカメラ移動・ズーム、ブルーム、被写界深度には反応せず、Black Holeの歪みは未対応です。

専用の強さは初期値**25%**で、戦闘の方向・距離・自分／敵の強さに影響されません。画面の信号自体は中央ですが、Bluetoothの最終指令には左右バランスを反映します。USB DualSenseでは質感を変えられ、通常振動では効果の強弱に追従します。PvP中、エリア移動中、キャラクターがいない間、非アクティブ時は停止します。[画面エフェクト一覧とタイミングの制約](SCREEN-EFFECT-HAPTICS.md)もご覧ください。表示装置とコントローラーの物理的な遅延は残ります。

### 標準の足音振動を強化

ゲームがすでに出している足音振動だけを強めます。スイッチと倍率を使うには、**DualSense / EdgeのUSB接続**と、**自動**または**DualSenseハプティクス**出力が必要です。Bluetooth・XInput・未接続時は操作できませんが、設定は保持します。

振動の一括スイッチに従い、戦闘グループとは個別に動きます。マウント中や非アクティブ時は停止し、範囲は**100～600%**、100%では標準の強さのままです。マウント、スピーカー音、戦闘振動は増幅しません。元の足音の強さはキャラクター・種族で異なる場合があり、倍率で自動的に揃えるわけではありません。

### 初期設定

初回設定ではライトと振動は未選択です。振動の一括スイッチは選択に従い、オフにしても下表の各分類の設定は保持します。振動タブで**初期設定に戻す**を実行すると、下表の設定に戻り、一括スイッチもオンになります。更新時は保存済みの値を保持します。

| 設定 | 初期値 |
| --- | --- |
| 振動を有効にする | 初回設定で選択。振動設定の初期化後はオン |
| 戦闘振動を有効にする | オン |
| 出力方式 | 自動。XInputが必要な場合は最初に接続された機器 |
| 自分の効果音に連動 | オン、強さ25% |
| ボスのスキル／通常の敵のスキル | 両方オン、敵の強さ100% |
| 被ダメージ時の振動 | オフ |
| 画面エフェクト | オン、強さ25% |
| 音の方向／距離減衰 | 両方オン。キャラクター基準、推奨3～25m |
| スキルの着弾方向に寄せる | オン、強さ100% |
| 戦闘の通常振動 | 強さ50%、1回120ms |
| Bluetooth振動の左右バランス | +85% |
| 標準の足音振動を強化 | オフ、倍率の保存値600% |

戦闘振動を有効にすると、立ち止まっていても短く2回振動して知らせます。通常の強さ変更やゲームに戻った際には繰り返しません。

## コマンド

`/bcef`で設定、`/bcef help`でコマンド一覧、`/bcef info`で案内を開きます。`/bcef trace`は診断記録を開始・停止し、診断タブを開きます。既存のマクロも `/bcef` に変更してください。

`/bcef <機能名> on`・`off`・`toggle`で切り替えます。例：`/bcef combathaptics off`。

| 機能名 | 切り替える内容 |
| --- | --- |
| `lighting` | ライトのカスタマイズ |
| `haptics` | 追加するすべての振動 |
| `combathaptics` | 戦闘の各分類をまとめて切り替え |
| `playersfx` | 自分のスキル・武器の振動 |
| `footsteps` | 標準の足音振動の強化 |
| `spatialhaptics` | 戦闘の左右方向 |
| `distancefade` | 戦闘の距離減衰 |
| `followimpact` | 自分のスキルの着弾方向への誘導 |

大文字・小文字は区別せず、自動保存します。設定画面を開かずにマクロでも使えます。上位スイッチがオフでも選択は保持し、必要なスイッチやUSB条件をチャットに表示します。`on`を繰り返しても通知の振動は再生しません。`footsteps off`は元の強さに戻すだけで、標準の足音振動を消しません。ボス・通常の敵・被ダメージ・画面のスイッチと数値設定は、現在は画面から変更します。

## 診断とプライバシー

この節は開発用プラグインとして読み込んだ場合のみ対象です。通常のプラグイン一覧やリポジトリのテスト版からインストールした場合、診断タブと `/bcef trace` は利用できません。開発用として読み込んだ Release ビルドでは利用できます。

診断タブには、接続、アクティブ状態、出力先とエラー、モーターテスト結果、発生元カウンター、計算後の左右の強さ、LB状態がまとまっています。

最初に記録を開始しようとすると、**記録を始める前に**が開き、保存する情報、2か所の保存先、履歴の保持と共有について説明します。**記録を開始**を押すと確認済みの状態を保存して記録を始めます。キャンセル、Escape、ポップアップの外側のクリックでは開始しません。以後も記録は手動で開始しますが、この案内は繰り返し表示しません。設定を初期化しても確認済みの状態は維持されます。

反応しない音や意図しない反応を調べるには：

1. 調べたい分類をオンにし、他の追加分類をオフにして切り分けます。
2. ギミックの直前に **`/bcef trace`** を実行するか、診断の**サウンドの記録を開始**を押します。
3. 再現したらもう一度 **`/bcef trace`** を実行するか、**記録を停止して保存**を押します。スキル名とおおよその経過時間を添えてください。

手動で停止するまで記録し、DLL横の `sfx-traces/` に1分ごとに保存して、直近**20件**を残します。`sfx-trace.json` は最後に保存した1件です。カメラのタイミング記録は `%LOCALAPPDATA%\DualSenseLighting\screen-haptics-timing.json` と、そのフォルダー内の別の `sfx-traces/` に保存します。

診断には、記録中でないときも保存済みの使用容量と2か所の保存先を表示します。記録を停止して保存が終わったら、ごみ箱アイコンを押し、確認画面で**記録を削除**を選びます。効果音とカメラのタイミング記録の最新ファイルと履歴を削除します。元には戻せません。

設定、音・リソース名、NPCと発生元の情報、位置、振動の経路、ローカルプロセスのアドレス、一部のネイティブメモリの内容を記録します。**音声は録音せず、自動送信もしません。** 1つのギミックの前後だけを短く記録すると調査しやすく、長い記録は1分あたり数十MBになる場合があります。公開前に内容を確認してください。[カメラのタイミング記録](SCREEN-EFFECT-HAPTICS.md#recording-timing-in-game)もご覧ください。

## 困ったときは

| 症状 | 確認すること |
| --- | --- |
| 開発用プラグインのアイコンが表示されない | `/xldev` → **Plugins → Clear cached images/icons** を選び、`/xlplugins` を開き直します。アイコンがなかった時点のキャッシュは、プラグインの再読み込みだけでは消えません。 |
| コントローラーを検出しない・出力がない | 先にWindowsで接続・ペアリングし、診断と出力方式を確認します。変換ソフトで実機を隠すと検出に影響する場合があります。仮想機器を使うならXInputを手動で選んでください。 |
| USBの標準振動は動くが、追加の戦闘振動がない | 振動の一括スイッチ、戦闘、使いたい分類をオンにし、自分・敵の強さを確認します。診断でネイティブ処理・発生元のエラーと距離の上限を調べます。 |
| Bluetoothが粗い・弱い・左右で違う | 通常振動の強さ・時間を調整し、2つのテストで切り分けます。診断に残る指令値と比較し、Bluetoothの左右バランスを調整してください。両側の質感は異なり、画面の強さは別設定です。 |
| 足音の設定が操作できない | DualSense / EdgeをUSB接続し、自動またはDualSenseハプティクスを選び、一括スイッチを確認します。再検出には約1秒かかる場合があります。元の足音振動がなければ新たに作りません。 |
| 特定のスキル・ボス効果が反応しない | 分類、音源の位置と距離、すでに標準振動があるかを確認します。不明な発生元・再生方式は除外される場合があります。そのギミックを記録してください。全ボス対応は保証していません。 |
| ボスの予告音も振動する | コンテンツ内ボス戦の広い分類では、発生元を確認できたNPCの詠唱・予告音も意図的に含めます。着弾音だけのフィルターではありません。 |
| 別のアプリに切り替えると消灯する | 制御を引き渡すための動作です。他のソフトが次に書き込むと設定を反映できますが、Steamの保存色を本プラグインから強制復帰させることはできません。 |
| ライトがちらつく・上書きされる | Steam、DS4Windowsなどが同時に書き込む場合があります。ゲーム中のライトは1つのツールに任せ、USBの標準機能はFFXIV側で設定してください。 |
| 下側LEDが動かない | ライトをオンにしてゲームをアクティブにし、1個以上を選びます。チェイスは2個以上、バウンスで5個を選ぶと全体が光って移動は見えません。 |
| パッチ後に機能が止まった | 診断、クライアントのリージョン・ビルド、Dalamud APIを確認します。APIが一致しても、音声・カメラのネイティブ処理の更新が必要な場合があります。 |

## ソースからビルド

**.NET 10 SDK**と対応する**Dalamud API 15**のライブラリを用意し、リポジトリのルートで実行します。

```powershell
./tools/build.ps1 -DalamudLibPath 'C:\path\to\Dalamud'
```

ローカルのXIVLauncher / XIVLauncherCNのライブラリを自動検出でき、`DALAMUD_HOME`も使えます。WSLからも同じWindows SDKのビルドを実行します。SDKがWindowsのPATHにない場合は、`--dotnet-path /mnt/c/path/to/sdk/dotnet.exe`で指定してください。

```bash
python3 tools/build-wsl.py
```

スクリプトは`Dalamud.NET.Sdk/15.0.0`で最適化したx64コードをビルドし、コントローラー・コア処理・翻訳のチェック、DLL名・バージョン・APIの照合を行い、`artifacts/plugin/`に出力します。標準パッケージは`artifacts/plugin/DualSenseLighting/latest.zip`です。公開用のパッケージにはインストーラーの翻訳とREADMEも追加されます。`-LockedRestore` / `--locked-restore`で、リポジトリ内の依存関係ロックファイルを検証できます。`-Probe` / `--probe`は、出力指令を送らないUSB・Bluetoothの読み取り専用チェックを追加します。

CIではWindows PowerShell 5で、ビルド時の引数の受け渡しと終了コードも確認します。同じチェックをローカルで実行できます。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./tests/BuildProcessChecks.ps1
```

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tools/generate-enemy-bosses.py --check
python3 tools/package-release.py
```

`artifacts/release/` に `latest.zip`、通常版のインストーラーフィード `pluginmaster.json`、チェックサム、リリース概要を作ります。3言語のREADMEと必要なライセンスを含み、ユーザー設定、診断記録、Dalamudライブラリ、コンパイラー依存ファイルは除外します。ローカルでのパッケージ作成だけでは公開されません。
